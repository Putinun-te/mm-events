# MM Events on Google Cloud

Terraform for running MM Events in your own GCP project: the Spring Boot API on Cloud Run,
MySQL 8 on Cloud SQL, secrets in Secret Manager and the static Nuxt site in Cloud Storage
behind a global external Application Load Balancer with Cloud CDN.

![GCP architecture](../../diagrams/gcp.png)

| Piece | Service | Notes |
|---|---|---|
| Backend image | Artifact Registry `mm-events` | Keeps the 10 newest versions |
| API | Cloud Run, 1 vCPU / 1 GiB, 0-2 instances | `railway` Spring profile, startup and liveness probes on `/actuator/health` |
| Load balancer | Global external Application LB | `/api/*` etc. to Cloud Run (serverless NEG), everything else to the bucket |
| Database | Cloud SQL MySQL 8.0, `db-f1-micro`, 10 GB SSD | Private IP only, TLS required, daily backups |
| Secrets | Secret Manager | DB password and JWT secret, both generated by Terraform |
| Frontend | Cloud Storage bucket + Cloud CDN | Website config serves `index.html` for unknown paths |

Design choices:

- **One origin for site and API.** The load balancer routes `/api/*`, `/actuator/health`,
  `/swagger-ui*` and `/v3/api-docs*` to Cloud Run and the rest to the bucket. Cloud Run's
  ingress is `INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER`, so its `run.app` URL is closed and
  all traffic goes through the load balancer.
- **Private database.** Cloud SQL has no public IP. It is reachable through Private
  Service Access, and Cloud Run reaches it with Direct VPC egress (no Serverless VPC Access
  connector to pay for). The app connects with plain JDBC and `sslMode=REQUIRED`, so no
  Cloud SQL connector library is needed in the image.
- **HTTPS needs a domain.** Without `domain`, the site is served over HTTP on the load
  balancer's IP. With `domain` set, Terraform adds a Google-managed certificate, an HTTPS
  listener and an HTTP-to-HTTPS redirect.
- **No secrets in Terraform state.** Both values come from ephemeral `random_password`
  resources and are written with write-only arguments (`secret_data_wo`, `password_wo`).
  Bump `secret_version` to generate new ones.

## Prerequisites

- A GCP project you own, with billing enabled, and `gcloud auth application-default login`
  as a user with Owner (or Editor + Project IAM Admin + Service Networking Admin) on it.
- Terraform 1.11 or newer (or the `hashicorp/terraform` Docker image), the gcloud CLI,
  Docker, Node.js 20.
- If your organisation enforces *Domain restricted sharing* or *Public access prevention*,
  the public bucket (`allUsers` read) is refused; use a project outside that policy.

## Deploy

All commands start in `deploy/terraform/gcp`.

```bash
cp terraform.tfvars.example terraform.tfvars   # set project_id (and domain, if you have one)
terraform init
```

**1. Enable the APIs and create the registry first**, because Cloud Run refuses to create
a service whose image does not exist yet:

```bash
terraform apply -target=google_artifact_registry_repository.backend
```

**2. Build and push the backend image:**

```bash
PROJECT=$(grep -E '^project_id' terraform.tfvars | cut -d'"' -f2)
IMAGE="asia-southeast1-docker.pkg.dev/$PROJECT/mm-events/backend:latest"
gcloud auth configure-docker asia-southeast1-docker.pkg.dev
docker build --platform linux/amd64 -t "$IMAGE" ../../../main_backend
docker push "$IMAGE"
```

**3. Create everything else** (Cloud SQL takes 10-15 minutes):

```bash
terraform plan -out tfplan
terraform apply tfplan
curl "$(terraform output -raw health_url)"     # {"status":"UP"}; the LB may need a few minutes
```

With a domain, create an `A` record for it pointing at `terraform output -raw
load_balancer_ip`. The certificate becomes active once Google sees that record (up to an
hour).

**4. Build and upload the frontend:**

```bash
API=$(terraform output -raw api_base_url)
BUCKET=$(terraform output -raw site_bucket)

cd ../../../main_frontend/concert1
npm ci --legacy-peer-deps
NUXT_PUBLIC_BACKEND_BASE_URL="$API" npx nuxt generate
gcloud storage rsync --recursive --delete-unmatched-destination-objects .output/public "gs://$BUCKET"
gcloud storage objects update "gs://$BUCKET/index.html" --cache-control="no-cache"
gcloud compute url-maps invalidate-cdn-cache mm-events --path "/*" --async
```

Open `terraform output -raw frontend_url`. Flyway creates the schema on the first start.

## Day-to-day

- **New backend version:** push a new tag and set `image_tag`, then `terraform apply`. If
  you push over `latest`, run
  `gcloud run services update mm-events-backend --region asia-southeast1 --image "$IMAGE"`.
- **Logs:** `gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="mm-events-backend"' --limit 50`
- **Cold starts:** with `min_instances = 0` the first request after an idle period waits
  for Spring Boot to start (roughly 20-40 s). Set `min_instances = 1` to avoid it, at about
  USD 10-15 a month more.

## Rough monthly cost

List prices in `asia-southeast1`, scale to zero, little traffic. Check the
[Google Cloud Pricing Calculator](https://cloud.google.com/products/calculator) before you
deploy.

| Item | USD / month |
|---|---|
| Load balancer forwarding rules (first five billed as one) | ~18 |
| Cloud SQL `db-f1-micro` + 10 GB SSD + backups | ~12 |
| Cloud Run (requests only, mostly free tier) | ~0-5 |
| Artifact Registry, Cloud Storage, CDN, Secret Manager | ~1 |
| **Total** | **~30-35** |

## Destroy

```bash
terraform destroy
```

This deletes the database and its backups (the default `deletion_protection = false`).
Set `deletion_protection = true` before you keep real data. The enabled APIs stay enabled,
and the VPC peering for Private Service Access is abandoned rather than deleted (Google
removes it once the Cloud SQL instance is gone); if `destroy` then reports the network is
still in use, wait a few minutes and run it again.

## Limits

- Deep links to client-side routes get `index.html` with HTTP status 404 (Cloud Storage
  website behaviour); the page renders normally.
- Photo uploads (`/api/upload`) use AWS S3 in the code and are not available here, as in
  the Railway demo.
- The login rate limit is kept in memory per instance.
